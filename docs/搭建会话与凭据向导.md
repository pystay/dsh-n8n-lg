# 搭建会话与凭据向导

> 这两个功能解决的是同一类问题：**AI 搭工作流的过程中，用户既看不清也管不着。**
>
> - **搭建会话 + 进度时间线**：把「AI 在做什么」显式化，并且让用户能**真的**暂停。
> - **凭据向导**：把「激活时才发现缺凭据」提前成「搭之前就知道缺什么」。

---

## 一、搭建会话（Build Session）

### 为什么需要

在此之前，AI 只是反复调 `n8n_add_nodes`。用户能看到画布刷新，但不知道：

- 一共打算做几步、现在第几步；
- 某一步到底成功没有（`added` 是多少、读回验证过了吗）；
- 中途想让它停一下——**根本停不下来**，因为没有任何「暂停」的语义。

### 模型

```ts
BuildSession {
  id, workflowId, goal,
  status: 'planning' | 'running' | 'paused' | 'completed' | 'failed' | 'cancelled',
  steps: BuildStep[],
  createdAt, updatedAt, finishedAt?, note?
}

BuildStep {
  id,            // 与 n8n_add_nodes 的 stepId 对应
  title, detail?,
  status: 'pending' | 'running' | 'done' | 'failed' | 'skipped',
  startedAt?, finishedAt?,
  snapshotId?,   // 该步写入前的自动快照 → 可回滚到这一步之前
  added?, skipped?, nodeCount?, verified?,
  issues?,       // 校验问题摘要（最多 5 条）
  error?
}
```

### Agent 的操作顺序

| 步骤 | 工具 | 说明 |
|---|---|---|
| 1 | `n8n_begin_build_session` | 声明**计划**：`goal` + 有序 `steps`（每项含 `id`/`title`/`detail?`） |
| 2 | `n8n_open_editor` | 让浮窗打开内嵌编辑器，用户开始看到画布与时间线 |
| 3 | `n8n_add_nodes`（带 `stepId`） | 每执行一步都带**相同的 `stepId`** → 结果自动落到对应步骤 |
| 4 | `n8n_get_build_session` | 需要时读回进度（含每步 `verified` / `snapshotId` / `error`） |
| 5 | `n8n_set_build_session_state` | 用户要求停/继续时切换状态 |
| 6 | 出错时 | `n8n_restore_workflow` 回到某一步之前的快照 |

> **关键约定**：`n8n_begin_build_session` 里的 `steps[].id` 必须和后续
> `n8n_add_nodes` 的 `stepId` 一致，否则结果不会挂到时间线上（会各自独立执行）。

### 暂停是「真生效」的

会话处于 `paused` 时，写入会被宿主的闸门拦下：

```json
{ "ok": false, "blocked": true, "error": "搭建会话 ab12cd34 处于暂停状态，写操作已被拦下；请先恢复…" }
```

被拦下的是：`n8n_add_nodes`、`n8n_update_workflow`，以及**浮窗里点的「启用/停用」**。
也就是说「停下来让我看看」不会出现「界面停了、后台还在写」的情况。

### 其他行为

- **新会话取代旧会话**：同一工作流再次 `begin` 时，旧的活跃会话自动标记为 `cancelled`。
- **取消/失败会收尾**：未完成的步骤标记为 `skipped`，`finishedAt` 落时间。
- **默认落盘**：写到 `~/.dsh/n8n-lg/sessions.json`（`persistState: false` 可关），重启后仍在；
  每个工作流保留最近 **10** 条会话。重启时遗留的 `running` 会话会被标成 `failed`
  （没人推进了，避免时间线永远卡住），`paused` 的保持 `paused`。
- **状态语义**：`completed` 只表示「AI 认为计划跑完了」，**不代表业务跑通**——
  业务是否成功要看执行结果（`n8n_get_execution_status`）。

## 二、凭据向导（Credential Wizard）

### 为什么需要

激活失败最常见的原因就是缺凭据，而 n8n 的 400 报错只提到节点名，
用户还得自己猜该建哪种凭据、去哪里建。

### 判定逻辑

```
需要什么 = 节点里已声明的 credentials 类型（权威）
         ∪ 内置的节点类型映射表（覆盖常见集成）

已有什么 = GET /api/v1/credentials 的 type 集合（只有类型，不含任何密钥）

差什么   = 需要 − 已有   → 逐条给出：凭据类型 / 涉及节点 / 配置入口
```

### 输出示例

```json
{
  "ok": false,
  "requirements": [
    { "node": "写入表格", "nodeType": "n8n-nodes-base.googleSheets",
      "credentialType": "googleSheetsOAuth2Api", "status": "missing", "disabled": false }
  ],
  "available": ["openAiApi"],
  "missing": [
    { "credentialType": "googleSheetsOAuth2Api", "nodes": ["写入表格"],
      "hint": "在 n8n 里新建 Google Sheets OAuth2 凭据并完成 Google 授权" }
  ],
  "unverified": [],
  "credentialsUrl": "http://127.0.0.1:5678/home/credentials",
  "note": "这是尽力而为的静态分析…本功能不会读取、也不会要求你提供任何密钥。"
}
```

### 边界（请如实理解）

- **尽力而为**：内置映射表覆盖常见节点，不可能覆盖全部社区节点；
  不在表里、也没声明凭据的节点会进 `unverified`（**不会**被当成「缺凭据」，避免误报）。
- **可选鉴权判断不了**：`httpRequest` 这类节点是否真的需要凭据取决于用户怎么配，因此被归为「无需凭据」。
- **禁用的节点不算缺失**：`disabled: true` 的节点不会阻止激活，因此不计入 `missing`。
- **权限不足时降级**：API Key 缺少 `credential:list` 权限时，仍会报告「需要哪些凭据」，
  并在 `scopeWarning` 里说明无法判断「已有什么」。
- **绝不涉及密钥**：只读凭据的**类型**；不读取、不存储、也**不会要求你把密钥贴进对话**。

│ ○ 连线                                     │
│ [暂停] [终止]                              │

## 四、实测记录

对真实 n8n（临时工作流，跑完即删）：

```
1) n8n_begin_build_session  → sessionId=..., progress={total:2, percent:0}
2) n8n_add_nodes(stepId=s1) → added=1, verified=true
3) n8n_get_build_session    → steps[0]=done(+1), steps[1]=pending, percent=50
4) n8n_set_build_session_state(paused)
5) n8n_add_nodes            → {ok:false, blocked:true, error:"…处于暂停状态…"}
   （工作流节点数未变化，确认没有写入）
6) n8n_set_build_session_state(running)
7) n8n_add_nodes            → ok:true，节点数 +1
8) n8n_check_credentials    → 列出缺失凭据类型与 /home/credentials 入口
```
