# 可视化搭建工作流（说需求 → AI 逐个节点搭出来 → 你全程看着）

> 目标：**不再丢给你一个 `.json` 让你自己 import**。你说需求，AI 在 n8n 里
> **一步一步把节点搭出来**，同时 **DSH 玻璃浮窗自动打开内嵌 n8n 编辑器**，
> 每保存一次就自动刷新，你能看着工作流"长"出来。
>
> 这一版的核心原则：**安全、可验证、可回滚**——每一次写入都是幂等的、写前校验、写后读回、
> 并且留下可撤销的快照。

---

## 用户怎么用（一句话）

在 DSH 里直接说需求，例如：

> 「帮我做一个工作流：收到 POST 请求后，把 body 里的 name 拼成问候语返回。」

AI 就会：创建工作流 → 打开内嵌编辑器 → 逐个加节点 → 连线 → 体检 → 激活 → 让你点「触发」试。

**不想让它自己搭？** 浮窗里每个工作流都有「编辑」按钮，可以随时自己上手改。
要自己改的时候，**先点掉「自动刷新」**，否则 AI 每保存一次就会重载编辑器、打断你的编辑。

## AI 的操作顺序（工具调用契约）

| 步骤 | 工具 | 说明 |
|---|---|---|
| 1 | `n8n_create_workflow` | 先建一个**空**工作流（`nodes: []`）。`settings` 缺省会自动补 `{}`；有校验错误会**拒绝创建**。 |
| 2 | `n8n_open_editor` | **立刻**把 `workflowId` 交给浮窗 → 编辑器自动弹出（即使面板当前是收起的）。带 `note` 说明当前在做什么。 |
| 3 | `n8n_add_nodes` | **一次加一步**，每次都传 `connections` 把线连上，并带一个稳定的 **`stepId`**。 |
| 4 | （重复 3） | 每加一步都可以再调 `n8n_open_editor` 更新 `note`；浮窗检测到 `updatedAt`/节点数变化会**自动刷新** iframe。 |
| 5 | `n8n_validate_workflow` | 激活前体检（重复 Webhook 路径等问题会被提前查出）。 |
| 6 | `n8n_activate_workflow` | 需要外部触发时才激活（工作流必须有真正的触发器节点：Webhook / Schedule 等）。 |
| 7 | `n8n_trigger_workflow` | 用 Webhook 路径试跑。⚠️ **激活后 webhook 注册是异步的，等 3–5 秒再触发**。 |
| 8 | `n8n_get_execution_status` / `n8n_list_executions` | 看结果。 |
| 9 | `n8n_restore_workflow` | 搭坏了？恢复到任意快照（一步撤销）。 |

### 写入为什么可以放心

`n8n_add_nodes` / `n8n_update_workflow` 都经过内部 `WorkflowEditor`：

| 保证 | 具体行为 |
|---|---|
| **幂等** | 同一 `stepId` 重复调用只写一次；节点按 `id`/`name` 去重，重试不会产生重复节点。 |
| **串行** | 同一工作流的写操作排队，避免「两个请求各自基于旧版本 PUT」导致丢更新。 |
| **全通道合并** | 连线按 `main` / `ai_languageModel` / `ai_tool` … **所有通道**逐分支追加并去重，不覆盖既有连线。 |
| **写前校验** | 缺 `id`/`name`/`type`、重名、重复 Webhook 路径、悬空连线、`knownTypes` 里不存在的类型 → **有 error 就不写**，把问题返回给 AI 去修。 |
| **写后验证** | 写入后读回确认节点存在，返回 `verified: true/false`。 |
| **自动快照** | 每次写入前留一份快照，返回 `snapshotId`，可随时回滚。 |
| **默认草稿** | `updateWorkflow` 带 `publishIfActive=false`，已发布的工作流不会被中间态自动重新发布。 |

> `n8n_add_nodes` 的返回里会带 `added` / `skipped` / `nodeCount` / `verified` / `snapshotId` / `issues`，
> 请**检查这些字段**再决定下一步，不要只看「没有报错」。

### 关键约束（踩过的坑）

- **`n8n_create_workflow` 的 body 必须有 `settings`**（工具已自动补 `{}`）。
- **`n8n_update_workflow` / `n8n_add_nodes` 的 PUT body 必须有 `name`/`nodes`/`connections`/`settings`**
  （工具会自动从当前工作流补全，不用你拼）。
- **`manualTrigger` 不算"可激活触发器"**：只有它的话 `publish` 会报
  `Workflow cannot be activated because it has no trigger node`。要么加 Webhook/Schedule，要么别激活。
- **Webhook 路径不能重复**：同一工作流里两个 Webhook 节点用同一 `path` → `publish` 报 **409 webhook path conflict**。
- **`publish` 会校验节点配置与凭据**：缺参数（如 `fileSelector`）或缺凭据（如 `googleSheetsOAuth2Api`）
  都会 **400**。缺凭据的节点可先 `"disabled": true` 绕过（可逆）——但这是**临时手段**，不代表业务能跑通。
- **节点类型必须是 n8n 真实支持的**：先用 `n8n_validate_workflow` 传 `knownTypes`，
  或跑 `npm run scan:workflows` 体检（见 `docs/收尾审计报告.md`）。
- **连线两端必须都是已存在的节点**：实测 n8n 会以
  `400 Workflow structure is invalid … unknown_connection_target` 拒绝保存。
  这条现在是**写前 error**（不再等 n8n 打回），所以「先加 Agent 节点，再连线」的顺序很重要。
- 每个节点需要 `id`、`name`、`type`、`typeVersion`、`position`；Webhook 节点还需要 `webhookId`。
- **`typeVersion` 要写数字**，字符串会被标 warning。

### 提示词模板（给用户）

> 我要一个工作流：<用大白话说清输入、处理、输出>。
> 请用 n8n 工具一步步搭，每加一个节点就在浮窗编辑器里让我看到，搭完告诉我怎么触发。

## 浮窗（玻璃 HUD）里能看到什么

- **编辑器**：浮窗会先向宿主确认 n8n 是否允许被内嵌：
  - **允许** → 直接内嵌 n8n 页面，并随保存自动刷新；
  - **不允许** → 显示说明（例如 `X-Frame-Options: SAMEORIGIN`）与
    **「在系统浏览器打开编辑器」**按钮，而不是留一片空白。

  顶部有 **自动刷新** 开关（**自己改时请关掉**）、**在系统浏览器打开**、**关闭**。
- **连接状态**：显示当前实际使用的实例（脱敏）与**来源**（浮窗设置 / 插件配置 / 环境变量 / 沙箱）。
- **工作流列表**：启用状态 + 「编辑」「启用/停用」「快照」「回滚」「触发」按钮。
- **触发 body**：面板里的 JSON 输入框会作为触发请求体发送。
- **最近执行**：状态徽章 + 时间；执行列表获取失败会**单独报错**，不会假装一切正常。

> 技术细节：桌面端主窗口 `webviewTag=false`，但配置了
> `setWindowOpenHandler → shell.openExternal`，所以「在系统浏览器打开」可用。
>
> ⚠️ **关于 iframe 内嵌**：n8n **2.43.5 实测会给所有 HTML 路由返回
> `X-Frame-Options: SAMEORIGIN`**，而浮窗页面跑在自定义协议（桌面端是 `dsh-app://app`）上、
> 与 n8n 不同源，因此浏览器会**拒绝渲染**该 iframe。前端读不到跨域响应头、无法自行判断原因，
> 所以由宿主用 **GET** 请求探测（`/api/dsh-n8n-lg/embed-check`）后告知前端。
>
> 一个踩过的坑：早先用 `curl -I`（HEAD）检查，看到「没有 X-Frame-Options」就以为可以内嵌——
> 实际 n8n 对 HEAD 返回 **404**，那个响应本来就不带安全头。**必须用 GET 探测。**
> 浮窗**不携带连接凭据**：保存后交给宿主 `ConnectionManager`，前端只拿脱敏状态。

## 连接是怎么统一的

以前浮窗和 AI 工具各自解析连接，会出现两个真实问题：只改地址时会沿用旧实例的 API Key；
在浮窗里填的配置对 AI 工具不可见。现在只有一个来源：

```
浮窗保存 → POST /api/dsh-n8n-lg/config → ConnectionManager（运行时覆盖）
                                          ↓
                        AI 工具 & 浮窗 都用同一个 client()
```

解析顺序：**运行时覆盖（浮窗）→ config → 环境变量 → 沙箱端点**。
地址与密钥**成对**保存，缺少任一项都会被拒绝（400），不可能出现「新地址 + 旧密钥」。

## 实机验证记录

用真实 n8n 跑通（临时工作流，跑完即删）：

```
注册工具数: 17
1) 创建工作流
2) 打开编辑器(focus)
3) 加 Webhook 节点（stepId=add-webhook）→ added=1, verified=true, snapshotId=...
4) 加 Code 节点 + 连接                → nodeCount=2，连接合并正确
5) 激活 → 等 4s → 触发                → 200，回显 nonce 一致
6) 清理：停用 → 删除 → 复查 404
```

`npm run e2e:real` 现在会**校验激活状态、回显 nonce、以及删除后是否真的消失**，
任一步失败都以非 0 退出——不再出现「清理失败但显示通过」。
