## 1. 安全：连接只有一份来源

**问题**：浮窗与 AI 工具各自解析连接。只改地址时会沿用旧实例的 API Key；在浮窗里填的配置对 AI 工具不可见；
未配置时工具干脆不注册，导致用户无法用浮窗去配置。

**做法**：新增 `src/connection.ts` 的 `ConnectionManager`。

- 解析顺序：**运行时覆盖（浮窗）→ config → 环境变量 → 沙箱端点**。
- 地址与密钥**成对**返回，缺少任一项都算「未配置」→ 不可能出现「新地址 + 旧密钥」。
- 浮窗**不再携带凭据**：保存时 `POST /api/dsh-n8n-lg/config` 交给宿主，之后所有请求由宿主发起。
- 浮窗只拿到脱敏状态：`baseUrl`（仅 origin，用于展示）+ `editorBaseUrl`（完整地址，用于拼接编辑器链接）+ `source`。
- 工具**始终注册**（17 个），未配置时在执行期给出可读错误。

**顺带修的同类问题**：`editorUrl()` 原本读浏览器 localStorage，连接来自环境变量/配置时会把编辑器开到**错误的实例**上。
现改为使用宿主的 `editorBaseUrl`（由独立验证发现）。

## 2. 安全：Webhook 路径不能越界

**问题**：白名单只做字符串匹配，`deploy/../other` 能命中 `deploy/*`，但 URL 解析后访问到别的前缀。

**做法**（`src/n8n/guard.ts`）：

- `isSafeWebhookPath()`：拒绝点段、**编码点段**（含二次编码）、段内分隔符、反斜杠、查询串/片段、协议与协议相对写法。
- 路径不安全时**一律拒绝**，即使白名单为空。
- `buildWebhookUrl()` 纵深防御：构造后校验最终 URL 仍在**同一源站**且落在 `/webhook/`（或 `/webhook-test/`）前缀内，并保留子路径部署。

## 3. 数据完整性：增量写入不再破坏工作流

**问题**：重试会重复追加节点；并发请求互相覆盖（丢更新）；只合并 `main` 通道导致 `ai_languageModel` 等连线被浅覆盖；
`PUT` 缺 n8n 要求的必填字段；已发布工作流的中间态会被自动重新发布。

**做法**：新增 `src/n8n/editor.ts` 的 `WorkflowEditor`。

| 保证 | 实现 |
|---|---|
| 幂等 | `stepId` 去重 + 节点按 `id`/`name` 去重；**无新节点时完全不写**（不产生无用快照） |
| 串行 | 每个工作流一条 Promise 队列，写操作排队执行 |
| 全通道合并 | 逐通道、逐分支追加 + 按 `(node,type,index)` 去重 |
| 写前校验 | 缺 `id`/`name`/`type`、重名、重复 Webhook 路径、悬空连线、`knownTypes` 外的类型 → **有 error 就不写** |
| 写后验证 | 读回确认节点存在，返回 `verified` |
| 可回滚 | 写前自动留快照，返回 `snapshotId` |
| 默认草稿 | `updateWorkflow(..., { publishIfActive: false })` |

新增工具：`n8n_validate_workflow`、`n8n_snapshot_workflow`、`n8n_restore_workflow`（共 **17** 个）。
快照存在内存（`src/n8n/snapshots.ts`，每流保留 5 份），**不落盘、不入库**。

## 4. 可验证：测试不再给假绿灯

- `scripts/e2e-real.mjs`：随机化工作流名与 webhook 路径；`publish` **只在 404/405 时**回退；
  **断言激活状态、断言回显 nonce、断言删除后复查 404**；任一步失败 → 非 0 退出。
  （旧版在停用/删除返回 500 时仍会打印「通过」并以 0 退出。）
- `scripts/scan-workflow-nodes.mjs`：跟随 `nextCursor` 翻页（旧版只看前 250 个）。
- 新增 `test/editor.test.ts`、`test/client-hud.test.ts`：后者用 `node:vm` + 极简 DOM 跑**真实**的
  `src/client/ui.js` / `store.js`，覆盖此前「没有 HUD 测试」的空白。

**测试数量：74 → 146**（8 个文件），`tsc --noEmit` 与构建均通过。

## 5. 桌面端体验

- **focus 自动展开**：AI 让浮窗打开编辑器时，即使面板当前是收起的也会展开。
- **`workflowId: null`** 表示打开工作流列表（此前被 `if (workflowId)` 忽略）。
- **编辑保护**：关闭「自动刷新」后，同一目标的 focus **不再重载 iframe**（避免打断手动编辑）；
  切换目标仍会导航。
- **真实错误**：保存失败、执行列表失败分别提示；每个操作按钮有 pending 禁用态；
  HTTP 非 2xx **不会被响应体里的 `ok:true` 掩盖**。
- **触发**：支持 `method` / `query` / 面板里的 JSON body；带上配置的 Webhook Header 鉴权
  （此前只有工具侧有，浮窗侧遗漏）；执行 ID 从正确的层级读取。
- **分页**：工作流列表支持 `cursor`；`limit` 有上限。
- **生命周期**：销毁时清理 interval、frame 超时、消息定时器；iframe 残留导航被取消。
- **可访问性**：输入框加 `aria-label`，iframe 加 `title`，按钮加 `title`。

## 6. 容器沙箱

- **就绪判定**：改用 `/healthz/readiness`（DB 已连接 + 已迁移），存活 200 不再被当作「可用」；
  老版本没有该端点时回退 `/healthz`。工具返回 `live` 与 `ready` 两个字段。
- **错误分类**：daemon 不可达/权限问题会**抛错**，不再被误判为「容器不存在」。
- **归属校验**：容器带 `dsh-n8n-lg.managed=true` 标签；同名但非本插件创建的容器**拒绝操作**。
- **日志**：检查退出码；`tail` 限制在 1–2000。
- **取消**：`AbortSignal` 贯通到 docker CLI 调用。
- **可选加固**：`sandbox.memoryLimitMb` / `cpus` / `pidsLimit` / `noNewPrivileges`（默认加 `no-new-privileges`）。

> 仍然如实声明：这是**普通的持久化 Docker 隔离**，适合**受信任**的工作流，**不是**可安全执行
> 任意恶意代码的强沙箱。
